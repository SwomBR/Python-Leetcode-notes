## 2. Problem Explanation

### What are we given?

`nums` — a list of integers (negative, zero or positive, possibly repeated).

### What must we return?

A list of **all** the different triplets `[a, b, c]` where:

- `a`, `b` and `c` come from **three different positions** of `nums`, and
- `a + b + c == 0`.

### The rules

1. **Different positions, not necessarily different values.** `[-1, -1, 2]` is fine if `-1` appears at two positions.
2. **No duplicate triplets.** Two triplets count as the same if they contain the same values, even if they were built from different positions or written in a different order. `[-1, 0, 1]` and `[0, 1, -1]` are the same triplet; list it once.
3. **Order doesn't matter** — neither the order of the triplets in the output nor the order of the numbers inside a triplet.
4. If no triplet works, return an empty list.

### Examples

**Example 1**

```text
Input:  nums = [-1, 0, 1, 2, -1, -4]
Output: [[-1, -1, 2], [-1, 0, 1]]
```

Several position choices give zero: positions 0, 1, 2 give `-1 + 0 + 1`; positions 1, 2, 4 give `0 + 1 + (-1)`; positions 0, 3, 4 give `-1 + 2 + (-1)`. The first two use the same values `{-1, 0, 1}`, so after removing repeats only two distinct triplets remain: `[-1, 0, 1]` and `[-1, -1, 2]`.

**Example 2**

```text
Input:  nums = [0, 1, 1]
Output: []
```

There's only one way to choose three positions, and `0 + 1 + 1 = 2`, not 0.

**Example 3**

```text
Input:  nums = [0, 0, 0]
Output: [[0, 0, 0]]
```

The only choice sums to 0.

### Constraints

- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

## 3. Everyday Analogy

> **Explain it like I'm five**

You have a pile of number cards. Some numbers are "owe" cards (negative) and some are "have" cards (positive). You want to find every group of **three** cards that cancels out exactly to zero.

First you **line the cards up from smallest to biggest**. Then you pick one card to be the "captain". For the remaining cards to its right, you put your **left hand** on the smallest one and your **right hand** on the biggest one, and add the three cards up:

- Total **too small**? Move your left hand one step right to a bigger card.
- Total **too big**? Move your right hand one step left to a smaller card.
- Exactly **zero**? Write the group down, then move both hands inwards.

When your hands meet, pick the next captain. And if the next captain has the same number as the last one, skip it — you'd only find the same groups again.

## 4. Step-by-Step Logic

1. **Reduce 3 numbers to 2.** If we fix the first number `a = nums[i]`, we need two other numbers summing to `-a`. That's the Two Sum problem ([001_two_sum.md](001_two_sum.md)).
2. **Sort first.** Sorting helps twice:
   - On a sorted array, Two Sum can be solved with **two pointers** in `O(n)` and `O(1)` memory.
   - Equal values become neighbours, so duplicates are easy to skip.
3. **Two pointers.** With `lo = i + 1` and `hi = n - 1`:
   - sum `< 0` → need something bigger → `lo += 1`;
   - sum `> 0` → need something smaller → `hi -= 1`;
   - sum `== 0` → record it, move both pointers.
4. **Avoid duplicate triplets.**
   - Skip `i` if `nums[i] == nums[i - 1]` (same first number already handled).
   - After recording a triplet, move `lo` past any copies of the value just used.
5. **Early stop.** If `nums[i] > 0`, every number after it is also positive, so no triplet can sum to zero — break.
6. **Why the pointer moves are safe:** if the sum is too small with `hi` at the largest available value, then `nums[lo]` can't be part of any solution with this `i` (every other partner is even smaller), so discarding it loses nothing. The same argument works for `hi` when the sum is too big.

## 5. Brute-Force Solution

### Algorithm

Try every combination of three positions `i < j < k`. When the sum is zero, sort the three values and put them in a set (the set throws away repeats). Finally convert the set to a list.

### Python code

```python
from typing import List


class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        n = len(nums)
        found = set()
        for i in range(n):
            for j in range(i + 1, n):
                for k in range(j + 1, n):
                    if nums[i] + nums[j] + nums[k] == 0:
                        found.add(tuple(sorted((nums[i], nums[j], nums[k]))))
        return [list(t) for t in found]
```

### Explanation

- `i < j < k` ensures three different positions and visits every combination exactly once.
- Sorting the three values gives one standard form, e.g. `(-1, 0, 1)`, so the set treats `[0, 1, -1]` and `[-1, 0, 1]` as the same triplet.
- Tuples are used because lists cannot be stored in a set (lists are not hashable).

### Complexity

- **Time:** `O(n³)` — there are `n(n-1)(n-2)/6` combinations, about 4.5 billion for `n = 3000`. This **times out** on LeetCode.
- **Auxiliary space:** `O(t)` for the set, where `t` is the number of distinct triplets found (this is also the size of the output).

## 6. Optimized Solution

### Idea — sort + fix one + two pointers

Sort the array. For each index `i` (the smallest number of the triplet), run a two-pointer scan on `nums[i+1..n-1]` looking for pairs that sum to `-nums[i]`. Skip duplicate values to keep triplets unique.

### Algorithm

1. Sort `nums`.
2. For `i` from `0` to `n - 3`:
   - If `nums[i] > 0`: break.
   - If `i > 0` and `nums[i] == nums[i - 1]`: continue.
   - `lo = i + 1`, `hi = n - 1`. While `lo < hi`:
     - `total = nums[i] + nums[lo] + nums[hi]`.
     - `total < 0` → `lo += 1`; `total > 0` → `hi -= 1`.
     - `total == 0` → record `[nums[i], nums[lo], nums[hi]]`, then `lo += 1`, `hi -= 1`, and keep moving `lo` while it equals the previous value.
3. Return the list of triplets.

### Python code (LeetCode-ready)

```python
from typing import List


class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        n = len(nums)
        result = []

        for i in range(n - 2):
            if nums[i] > 0:
                break                          # smallest value positive: no more zeros possible
            if i > 0 and nums[i] == nums[i - 1]:
                continue                       # same first value as before: skip duplicates

            lo, hi = i + 1, n - 1
            while lo < hi:
                total = nums[i] + nums[lo] + nums[hi]
                if total < 0:
                    lo += 1                    # need a bigger sum
                elif total > 0:
                    hi -= 1                    # need a smaller sum
                else:
                    result.append([nums[i], nums[lo], nums[hi]])
                    lo += 1
                    hi -= 1
                    while lo < hi and nums[lo] == nums[lo - 1]:
                        lo += 1                # skip copies of the value just used

        return result
```

> Note: `nums.sort()` sorts the caller's list in place. That's fine on LeetCode. If you must not change the input, use `nums = sorted(nums)` (costs `O(n)` extra memory).

### Alternative: sort + hash set for each first number

Instead of two pointers you can solve the inner Two Sum with a set, exactly like [001_two_sum.md](001_two_sum.md). Sorting is still used to skip duplicates.

```python
from typing import List


class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums = sorted(nums)
        n = len(nums)
        result = []
        for i in range(n - 2):
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            seen = set()
            j = i + 1
            while j < n:
                need = -nums[i] - nums[j]
                if need in seen:
                    result.append([nums[i], need, nums[j]])
                    while j + 1 < n and nums[j + 1] == nums[j]:
                        j += 1                 # same largest value would repeat the triplet
                seen.add(nums[j])
                j += 1
        return result
```

For a fixed `i`, each triplet is identified by its largest value `nums[j]` (because `need` was seen earlier in sorted order, so `need <= nums[j]`). Skipping repeated `nums[j]` values after a match therefore prevents duplicates. This is also `O(n²)` time, but it needs `O(n)` extra memory for `seen`.

(Two-pointer version)

| Line | What it does | Why |
|---|---|---|
| `nums.sort()` | Sorts ascending. | Enables two pointers and puts duplicates next to each other. |
| `result = []` | Output list. | — |
| `for i in range(n - 2):` | `i` is the position of the smallest value in the triplet. | We need two more positions after `i`, so `i` stops at `n - 3`. |
| `if nums[i] > 0: break` | Early exit. | All later values are `>= nums[i] > 0`, so the sum would be positive. |
| `if i > 0 and nums[i] == nums[i - 1]: continue` | Skip a repeated first value. | It would find exactly the same triplets as the previous `i`. |
| `lo, hi = i + 1, n - 1` | Pointers at the smallest and largest remaining values. | Classic two-pointer setup on a sorted range. |
| `while lo < hi:` | Run until the pointers meet. | `lo` and `hi` must be different positions. |
| `total = nums[i] + nums[lo] + nums[hi]` | Current sum. | — |
| `if total < 0: lo += 1` | Increase the sum. | Moving `lo` right gives a value that is the same or bigger. |
| `elif total > 0: hi -= 1` | Decrease the sum. | Moving `hi` left gives a value that is the same or smaller. |
| `result.append([...])` | Record a zero-sum triplet. | Values are in sorted order: `nums[i] <= nums[lo] <= nums[hi]`. |
| `lo += 1; hi -= 1` | Move both pointers. | With `nums[i]` and `nums[lo]` fixed, `nums[hi]` is forced; we need new values on both sides. |
| `while lo < hi and nums[lo] == nums[lo - 1]: lo += 1` | Skip copies of the `lo` value just used. | Otherwise the same triplet would be recorded again. (Skipping `hi` copies is unnecessary: if `lo` has a new, larger value, the matching `hi` value must be smaller, so the old `hi` copies are passed over by `hi -= 1` naturally.) |
| `return result` | Done. | — |

|---|---|---|---|---|---|---|---|---|

## 9. Concepts, Data Structures, and Patterns

- **Reduction:** k-Sum → (k−1)-Sum by fixing one element. 3Sum = loop + Two Sum.
- **Sorting** (`O(n log n)`): makes order-based reasoning possible and groups duplicates.
- **Two pointers on a sorted array:** move the pointer that moves the sum in the needed direction. Each step discards one element safely, so the scan is `O(n)`. The same pointer-shrinking idea appears in [010_container_with_most_water.md](010_container_with_most_water.md).
- **Duplicate handling by skipping equal neighbours:** a standard trick for "unique combinations" problems.
- **Hash set alternative:** the [001_two_sum.md](001_two_sum.md) complement idea.
- **Related problems:** Two Sum II (LeetCode 167), 3Sum Closest (LeetCode 16), 4Sum (LeetCode 18), 3Sum Smaller (LeetCode 259, premium).

## 10. Complexity Analysis

| Approach | Time | Auxiliary space | Explanation |
|---|---|---|---|
| Brute force | `O(n³)` | `O(t)` | Every triple of positions; the set holds `t` distinct answers. |
| Sort + two pointers (optimized) | `O(n²)` | `O(n)` worst case (sorting's temporary buffer); `O(1)` apart from the sort | Sorting is `O(n log n)`. For each of up to `n` values of `i`, the pointers move inward at most `n` steps in total → `O(n²)`, which dominates. Python's Timsort may use up to `O(n)` temporary memory; apart from that only `i`, `lo`, `hi`, `total` are used. The output list is not counted. |
| Sort + hash set | `O(n²)` | `O(n)` | `seen` can hold up to `n` values for each `i` (recreated each time). |

**How many triplets can there be?** At most `O(n²)` distinct triplets (once the first two values are chosen, the third is fixed), so even writing the output fits within `O(n²)`.

## 12. Common Mistakes and Debugging

1. **Forgetting to skip duplicate first values.** `[-1, -1, 0, 1]` would output `[-1, 0, 1]` twice.
2. **Skipping duplicates of `i` with `nums[i] == nums[i + 1]`.** That skips the *first* copy instead of the later ones, which can lose triplets like `[-1, -1, 2]` (it needs the first `-1` as `i` and the second as `lo`). Compare with the *previous* element.
3. **Not moving pointers after a match.** `while lo < hi` would loop forever.
4. **Skipping duplicates before checking the sum.** If you jump `lo` forward with `while lo < hi and nums[lo] == nums[lo + 1]: lo += 1` *before* computing `total`, then for `[-2, 1, 1]` the pointer `lo` jumps onto the second `1` (where `hi` already is) and the valid triplet `[-2, 1, 1]` is lost. Skip copies only *after* recording a triplet.
5. **Using a set of lists.** Lists aren't hashable; use tuples.
6. **Breaking on `nums[i] >= 0`.** That would miss `[0, 0, 0]`. Break only when `nums[i] > 0`.

**Debugging tip:** print `i, lo, hi, total` inside the loop for the sorted Example 1 and compare with the dry-run table.

## 13. Practice Questions

**Q1. List the distinct zero-sum triplets of `[-2, 0, 1, 1, 2]` by running the two-pointer algorithm.**

<details><summary>Hint</summary>The array is already sorted. Start with `i = 0` (value -2).</summary></details>

**Answer:** `i = 0` (-2): `lo=1, hi=4`: `-2+0+2 = 0` → record `[-2, 0, 2]`; `lo=2, hi=3`: `-2+1+1 = 0` → record `[-2, 1, 1]`; pointers cross. `i = 1` (0): `0+1+2 = 3` → `hi=3`; `0+1+1 = 2` → `hi=2`, stop. `i = 2` (1): positive → break. Result: `[[-2, 0, 2], [-2, 1, 1]]`.

**Q2. 3Sum Closest (LeetCode 16): return the sum of three numbers closest to `target` (exactly one answer is guaranteed).**

<details><summary>Hint</summary>Same sort + two pointers; track the sum with the smallest `abs(total - target)`.</summary></details>

**Answer:**

```python
def three_sum_closest(nums, target):
    nums = sorted(nums)
    best = nums[0] + nums[1] + nums[2]
    for i in range(len(nums) - 2):
        lo, hi = i + 1, len(nums) - 1
        while lo < hi:
            total = nums[i] + nums[lo] + nums[hi]
            if abs(total - target) < abs(best - target):
                best = total
            if total < target:
                lo += 1
            elif total > target:
                hi -= 1
            else:
                return total
    return best


assert three_sum_closest([-1, 2, 1, -4], 1) == 2
assert three_sum_closest([0, 0, 0], 1) == 0
```

**Q3. Count the triplets of positions `i < j < k` whose sum is strictly less than `target` (3Sum Smaller).**

<details><summary>Hint</summary>After sorting, if `nums[i] + nums[lo] + nums[hi] < target`, then every `hi'` with `lo < hi' <= hi` also works — that's `hi - lo` triplets at once.</summary></details>

**Answer:** Sorting doesn't change the number of position triples, so it's safe here.

```python
def three_sum_smaller(nums, target):
    nums = sorted(nums)
    count = 0
    for i in range(len(nums) - 2):
        lo, hi = i + 1, len(nums) - 1
        while lo < hi:
            if nums[i] + nums[lo] + nums[hi] < target:
                count += hi - lo
                lo += 1
            else:
                hi -= 1
    return count


assert three_sum_smaller([-2, 0, 1, 3], 2) == 2   # (-2,0,1) and (-2,0,3)
assert three_sum_smaller([], 0) == 0
assert three_sum_smaller([0, 0, 0], 1) == 1
```

**Q4. Why is it safe to move only `lo` (and not also `hi`) past duplicates after a match?**

<details><summary>Hint</summary>What value must `nums[hi]` have to match the new `nums[lo]`?</summary></details>

**Answer:** After skipping, `nums[lo]` is strictly larger than the value just used. To keep the sum at zero, the partner must be strictly smaller than the old `nums[hi]`. Any remaining copies of the old `nums[hi]` would now make the sum too big, so the `total > 0` branch moves `hi` past them automatically — no duplicate triplet can be recorded.
